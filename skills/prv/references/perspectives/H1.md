# Method: requirement traceability on a plan
1. Every requirement id and acceptance condition in N0 maps to a named design component or contract in N1; list unmapped ones.
2. No N1 statement contradicts an N0 statement (scope, behavior, error handling, schema).
3. Every claim N1 makes about existing code ("currently", "base", "keeps", "unchanged") matches the code.
4. Every rule in the repository AGENTS.md files that the design touches is followed or the deviation is justified.
5. When N0 states a solution (the issue body, a comment, the user's words), N1 takes it as its mechanism or quotes the N0 requirement it fails; report a design that replaces it without that quote.
6. Public contract (REST/MCP responses, config keys, schema): every change is listed with its effect on existing deployments.
