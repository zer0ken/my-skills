# Method: removal of the cause and alternative structures on a plan
1. N1's mechanism removes the cause the requirements name, and it is the smallest known one that meets them; report a mechanism a smaller known one would replace, with that one.
2. Judge whether a feasible alternative structure is better in data flow, state ownership, or call cost. The cost side of that judgment rests on the plan's hot paths and their budgets in items 3-5: an alternative is better in cost only against a stated budget and its evidence, so a plan that gives no budget for a hot path leaves this perspective undecided there, which is itself a finding.
3. List every hot path the design adds or changes (per request, per document, per candidate, per row): its query shape, model calls, embedding calls, and network round trips per unit.
4. Each hot path has a stated budget and the evidence that it holds: a proof of the bound from the code and the documented semantics of the system it runs on, with its premises and their sources, or, where no proof settles it (constants on real data, model latency, behaviour the documentation leaves undefined), a measurement on realistic data size (not test seeds) with the command (EXPLAIN ANALYZE, PROFILE, benchmark).
5. Comparison with main on the same input is planned for search score and recovery where they are affected, and for upsert time where no proof settles it.
